確認你的授權情境

今天的學員可能有三種授權情境，部分步驟做法不同，請先確認自己是哪一種，並在本節標題旁的「我的授權情境」點選 A、B 或 C，頁面就只會顯示你要做的步驟，再點一次可以取消，回到顯示全部；有不同做法的單元標題旁也有同一個切換，選一次全部同步

情境 你的帳號
A 有授權 有 Microsoft 365 Copilot 授權 (Premium)，登入後顯示「M365 Copilot (Premium)」
B 無授權＋Pay-as-you-go 無授權 (Basic)，只有 Copilot Chat，但公司已啟用 Pay-as-you-go 點數計費
C 無授權＋無 Pay-as-you-go 無授權 (Basic)，只有 Copilot Chat，公司也未啟用 Pay-as-you-go；建立 Agent 時「知識」區只能加入公開網站網址，無法加入檔案

簡報重點速查

  • Agent = LLM + 上下文 + 工具: LLM 是大腦，上下文是眼睛 (知識、對話歷史、使用者情境、可用工具、護欄)，工具是手腳

  • 上下文的品質，才是 Agent 能力的真正關鍵: 給足背景資訊，中等模型也能勝過資訊匱乏的頂級模型

  • Copilot Chat vs Agent: Chat 每次從零開始；Agent 把指示、知識與能力先封裝好，同一件事會做超過 3 次，就做成 Agent

  • Agent Builder 的主戰場在上下文: 知識庫決定它知道什麼，指示決定它怎麼想

  • Skill (預覽): 把專業流程封裝成模組，用到才載入；Agent Builder 僅限 Frontier 計畫租戶，每個 Agent 最多 8 個

  • 授權: 只用指示和公開網站的 Agent 不需 Copilot 授權；用到 SharePoint、OneDrive 或上傳檔案，需要 Microsoft 365 Copilot 授權或 Pay-as-you-go

  • 三個可以做 Agent 的地方: Agent Builder (No-code)、Copilot Studio (Low-code，流程與整合)、Microsoft Foundry (Pro-code，完全自訂)

實作暖身｜先看內建 Agent 怎麼把提示詞變成專業流程

三種內建 Agent 的差異

內建 Agent它主要幫你做什麼最適合的問題不適合的問題
Prompt Coach幫你診斷提示詞缺口，改寫成更清楚的問法「我想問得更準」「幫我把需求變成好提示詞」直接請它查資料或做長篇研究
Researcher / 研究工具自己規劃研究步驟，搜尋、閱讀、整理來源「幫我研究案例、趨勢、風險、方案」需要立刻回答的小問題、單一文件內查找
Analyst / 分析師拆解資料問題，分析表格、數字、趨勢與異常「幫我看數據哪裡有問題」「比較各單位表現」沒有資料、只想做文字改寫的任務

Demo 0-1Prompt Coach:把模糊需求變成好提示詞

操作步驟

  1. 先在一般 Copilot Chat 貼上「原始提示詞」，觀察回答是否籠統

  2. 切換到 Prompt Coach，貼上同一段原始提示詞

  3. 記下 Prompt Coach 指出的缺口

  4. 把 Prompt Coach 改寫後的提示詞，再貼回一般 Copilot Chat 比較結果

原始提示詞

幫我查一下公司內部作業規定，整理重點給我

給 Prompt Coach 的提示詞

我是台電的同仁，常常需要請 Copilot 幫我查公司內部的作業規定，但它的回答常常太籠統、沒有標出依據哪一份文件。請幫我檢視這個需求，告訴我我的提問少了哪些資訊，並示範改寫成一句更精準的提示詞，用條列方式回覆，三百字以內

重點提示

  • Prompt Coach 的價值不是替你回答問題，而是幫你把「想問什麼」整理清楚

  • 等一下寫 Agent 指示時，也要用同樣方式補齊:角色、資料來源、回答流程、格式與邊界

Demo 0-2Researcher / 研究工具:把研究任務變成有來源的報告

操作步驟

  1. 在一般 Copilot Chat 貼上 Researcher 提示詞，觀察它是否立即給出概略回答

  2. 切換到 Researcher / 研究工具，貼上同一段提示詞

  3. 如果它反問研究範圍、年份或地區，依自己的需求補充

  4. 等報告完成後，至少點開 2 個來源，確認是否真的支持結論

  5. 用「追問提示詞」要求它把研究結果收斂成適合台電部門試做的方向

Researcher 提示詞範本

我是台電的同仁，正在規劃部門導入 AI Agent。請幫我研究國內外電力公司或公用事業公開分享過的生成式 AI 與 AI Agent 應用案例，依「客服、設備維運、內部知識查詢、行政作業」分類，每個案例說明單位名稱、做了什麼、帶來什麼效益與資料來源；最後歸納 3 個適合台電部門先試做的方向，用繁體中文，表格加條列呈現

追問提示詞

請把上面的研究結果收斂成「台電部門可以在 30 天內試做的 3 個 Agent 題目」，每個題目請列出目標使用者、需要準備的資料、第一個可測試問題、可能風險，並依容易度排序

有檔案版提示詞

請分析我上傳的住宿選擇比較表，找出最適合四人家庭入住兩晚的前三個選項。請說明你用了哪些欄位、如何計算兩晚總價、如何處理親子友善與停車條件，最後用表格列出推薦排名、理由、可能限制

無檔案版提示詞

假設我有一份各區處每月案件量、平均處理天數、逾期件數與人力數的表格，想找出哪幾個區處可能需要優先改善。請說明你會如何分析這份資料、會看哪些欄位與指標、如何避免只看案件量就誤判，最後會用什麼表格或圖表呈現

追問提示詞

請把剛剛的分析方法改成一份「給主管看的摘要格式」，包含:一個結論、三個觀察、兩個需要補資料才能判斷的地方，以及一個建議的下一步

單元 01｜建立第一個 Agent：花蓮旅遊助理

直接從實作開始：先認識 Agent Builder 欄位，再用花蓮素材建立、測試並優化第一個 Agent

Demo 1-1Agent Builder 介面與建立流程

操作步驟

  1. 在 Copilot Chat 點左側「代理程式」→「新的代理程式」→ 點「跳過」，進入設定頁

  2. 切換到「設定」頁，對照下表由上到下認識各欄位

  3. 注意: 編輯頁面沒有測試窗，不能一邊編輯一邊提問，要先按右上角「建立」，再從左側代理程式清單打開 Agent 對話；之後每次修改都要按「更新」，再開新對話測試

欄位 (由上到下) 放什麼 小提醒
名稱 Agent 的名字 最多 30 字元，短、好記、看得出用途
圖示 代表 Agent 的圖示 可用 AI 產生、從圖庫選或上傳 PNG
模型 預設回應模式 (自動/快速回應/深入思考) 使用者可以自行切換
描述 一段話說明它能做什麼、服務誰 最多 1,000 字元，會顯示給使用者看
指示 角色、知識規則、回答流程、格式、邊界、語氣 最多 8,000 字元，是品質的關鍵
知識 網站、SharePoint/OneDrive、Teams、Email、上傳檔案、connectors 上傳後顯示「Preparing」；這裡也有「搜尋所有網站」開關
Skills 封裝好的專業流程模組 預覽功能，僅限 Frontier 計畫租戶
工作內容 網路搜尋、程式碼解譯器、影像產生 依需求開啟
建議的提示 使用者打開時看到的範例問題 設計好能大幅降低使用門檻

我想在 Agent Builder 建立一個只根據我上傳的資料回答問題的 Agent，請用條列方式告訴我，名稱、描述、指示、知識、功能、建議的提示這幾個欄位各自應該填什麼，以及哪兩個欄位最影響回答品質，每個欄位說明不超過兩行

  1. 點左側「代理程式」→「新的代理程式」→ 點「跳過」，進入設定頁後，先加入知識檔

  2. 填名稱與描述

  3. 用下方提示詞，請 Copilot Chat 把六項定義轉成指示初稿;修改後貼入「指示」欄

Demo 2-3自我測試與優化

操作步驟

  1. 換個角度，假設自己是第一次使用這個 Agent 的同事，設計三類題目: 正常問題 3 題、模糊問題 1 題、超出範圍問題 1 題

  2. 打開自己的 Agent 開一個新對話，依序提問並記錄結果

  3. 挑一題回答不理想的題目，比照 Demo 1-7 的做法: 開一個新的 Copilot Chat 對話，貼上下方提示詞 (連同指示全文與有問題的回答)，請它診斷並改寫對應段落

  4. 依建議修改「指示」欄，按右上角「更新」後開一個新對話重問同一題，完成至少 1 次優化
